# 简历项目描述

## 项目名称

**SignalWatch｜多源舆情监测与危机预警 Agent｜个人项目**

## 一句话介绍

面向品牌公关和舆情团队的 AI 辅助监测工作台，在声明的数据源范围内完成多源采集、事件聚合、规则/模型研判、告警送达和人工复核。

## 简历 Bullet（技术/后端方向）

- 设计并实现多源舆情监测 Agent，打通微博、抖音、今日头条、B站、中新网等公开来源及授权供应商接口，形成采集、规范化、事件聚合、研判、告警和人工处置闭环。
- 设计可审计的 Agent 运行轨迹，记录查询计划、来源选择、规则研判、模型调用、告警送达和失败原因；模型超时或来源异常时自动保留规则结果并显式标记覆盖缺口。
- 构建规则 + OpenAI 兼容模型的分层研判链路，先通过关键词和风险规则预筛，仅将命中候选送入模型；采用“模型不得降低规则风险”的保守合并策略，并支持 Webhook/邮件告警。
- 使用 SQLite 实现证据、分析、告警、运行轨迹和人工反馈持久化，提供来源首次发现时间、去重告警和 Markdown 证据报告。
- 建立 23 条开发回归集和 15 条独立 Holdout，覆盖安全事故、政策、竞品误命中、谣言、提示注入和讽刺表达；规则版 Holdout 告警召回率 54.55%，接入 deepseek-flash 并校准合并策略后提升至 100%（仅限合成评测），26 个自动化测试全部通过。
- 提供 Docker、GitHub Actions、运行轨迹页面和演示脚本，支持本地及容器化复现。

## 简历 Bullet（AI/Agent 方向）

- 设计“计划 → 采集 → 观察 → 规则研判 → 模型辅助 → 告警 → 人工反馈”的可审计 Agent 工作流，避免将普通爬虫包装成自主 Agent。
- 实现 OpenAI 兼容模型适配层，统一处理 DeepSeek、本地小模型和 vLLM 等推理服务；通过候选预筛、结构化 JSON 输出、失败回退和风险不降级策略控制成本与稳定性。
- 构建开发集 + 独立 Holdout 的评测体系，定位规则引擎在讽刺、隐晦安全隐患和未证实传闻上的盲点；针对模型过度升级风险的问题设计“最多提升一级”合并策略，并记录调参前后指标。

## 简历 Bullet（产品方向）

- 将舆情监测拆分为持续监听、危机预警、事件研判、人工复核和证据报告五个核心场景，明确“无结果、覆盖不足、来源失败、无法判断”四种状态，避免误导用户。
- 设计数据源能力矩阵和分级授权流程，对公开热榜、登录态接口和授权供应商分别标注覆盖范围与验证状态。
- 建立从告警候选到人工处置的反馈闭环，并将误报、漏报和模型失败样本回用于评测。

## 量化指标的准确写法

可以写：

> 规则版在 15 条独立合成 Holdout 上的告警召回率为 54.55%，接入 deepseek-flash 并校准后达到 100%；26 个自动化测试通过。以上为合成回归结果，不代表真实业务准确率。

不要写：

> 舆情识别准确率 100%。

前者说明了数据范围和指标，后者会被面试官视为误导。

## 面试时需要主动说明的限制

- 微博、抖音当前是公开热榜，不是站内全文搜索。
- 合成评测集不能代表真实业务准确率。
- 当前默认无真实模型，需配置模型服务后才能展示 AI 研判。
- SQLite 和单进程调度是 MVP 架构，不代表生产规模。
- 平台接口和数据转售需要合同、授权与法律审查。
