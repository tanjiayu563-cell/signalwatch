# SignalWatch 项目提交说明

## 定位

SignalWatch 是一个有明确数据边界、可审计、带人工复核的多源舆情监测与危机预警 Agent MVP。

它解决的不是“自动处理危机”，而是：

- 在声明数据源范围内发现可能相关的信号
- 将重复帖子聚合为事件而不是链接列表
- 对命中内容进行规则与可选模型研判
- 保留证据、覆盖缺口和 Agent 决策轨迹
- 在达到风险阈值时发送告警
- 将最终判断交给人

## 当前实现

- 微博热搜、抖音热榜、今日头条热榜、B站热门、中新网 RSS
- 登录态与授权供应商统一接入协议
- SQLite 证据、分析、告警、运行轨迹和人工反馈持久化
- 规则引擎与 OpenAI 兼容模型适配层
- Webhook、企业微信、飞书和 SMTP 邮件告警
- Markdown 事件报告
- Docker、Docker Compose、GitHub Actions
- 26 个自动化测试
- 23 条开发回归集 + 15 条独立合成 Holdout

## 规则基线

| 指标 | 结果 |
|---|---:|
| 规则版 Holdout 告警召回率 | 54.55% |
| 规则 + deepseek-flash Holdout 告警召回率 | 100% |
| 规则 + deepseek-flash Holdout 告警精确率 | 100% |

以上结果来自 15 条独立合成 Holdout，不代表真实业务准确率。模型版还采用风险最多提升一级的校准策略，防止过度告警。

## 演示步骤

1. 启动：`python3 app.py`
2. 输入监测对象并扫描
3. 查看 Agent 轨迹
4. 打开事件证据链
5. 标记人工状态
6. 导出 Markdown 报告
7. 展示告警 Webhook/邮件
8. 展示评测报告

## 项目亮点

- 不是纯聊天界面，而是完整的数据、研判、告警和人工闭环
- Agent 每一步可解释、可审计
- 模型失败不会破坏采集和规则告警
- 明确区分无结果、覆盖不足、来源故障和无法判断
- 不把“公开可见”错误等同于“可以任意商业使用”

## 已知限制

- 微博、抖音当前是公开热榜，不是站内全文检索
- 真实模型需要用户提供 API 凭据或本地推理服务
- SQLite 和单进程调度适合 MVP，不是生产规模架构
- 合成评测集不能代替真实历史事件和人工双标
- 平台授权、数据存储和转售需要合同与法律审查
